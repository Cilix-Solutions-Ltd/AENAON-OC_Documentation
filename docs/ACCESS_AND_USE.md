# Access and use

[Repository home](../README.md) · [Getting started](GETTING_STARTED.md)

## Documentation and service access

Open Call beneficiaries receive read-only access to approved repository contents. They cannot push changes, merge pull requests or modify documentation. Documentation access does not confer access to proprietary software, hosted workspaces, APIs, credentials or restricted artefacts. Contact the responsible provider through the project onboarding route to agree access for an approved activity.

Each owner controls the software, APIs, proprietary material and services it authorises for Open Call use. Browser accounts, API scopes and deployment resources are separate arrangements. Do not assume that a documented interface is enabled for every account.

## Ownership, Background IP and licences

Tools and associated Background IP remain subject to their owners' rights and applicable project agreements, Open Call agreements and provider licence terms. This repository documents available arrangements; it does not grant a software licence, require source-code distribution or introduce new legal provisions. It does not supersede those agreements or terms. No open-source software licence is added by this catalogue.

## External resources and downloads

Use manuals, releases, registries and download locations approved by the relevant provider. Check the intended version, audience and access conditions before following external instructions. Links do not transfer ownership or grant redistribution rights. Proprietary hosted services do not imply access to source code, deployment packages, databases or internal interfaces. Only use downloadable artefacts explicitly supplied and authorised by the owner.

## Confidential and operational information

Agree permitted inputs, data-sharing channels, recipients and handling requirements with the provider before uploading information. Use sanitised, synthetic or representative data where agreed if production data cannot be shared. Do not assume that removing names makes operational information safe to disclose.

Do not store passwords, API keys, tokens, sensitive infrastructure information, live target details, confidential reports or operational datasets in this repository, its issues or pull requests. Share these only through the agreed secure project/provider channel. Documentation examples and attachments must be suitable for the repository's beneficiary audience. If sensitive material is disclosed accidentally, notify CILIX through a secure channel for remediation; do not repeat it in a public discussion.

## Authorised testing and monitoring

Security assessments require explicit authorisation of the target environment and agreed scope. Live operational telemetry and monitoring require prior authorisation. Repository access and tool accounts do not authorise scanning, telemetry collection or incident-response actions. Follow each profile's technical boundaries; potential exposure is not proof of exploitation, and a preparation workbench is not a managed monitoring service.

## Questions and corrections

Use the responsible provider's onboarding route, or [info@aenaon-project.eu](mailto:info@aenaon-project.eu) for project coordination. Partners propose updates through [pull requests](../CONTRIBUTING.md); CILIX reviews and only authorised CILIX staff merge approved updates.
